Eco-Accessible Wheelchair

A small autonomous wheelchair that carries a teddy bear through a timed course, crosses a bump and launches a piece of recycling over a wall. An Arduino drives it, and a servo fires a mousetrap launcher.

The build

My role

I was the Electrical Lead on a team of six. I led the design of the control circuit and its wiring, which is documented in an AutoCAD diagram, working with the testing and wiring members of the team.

Electrical system

How it works

The Arduino sends PWM and direction signals to an L298N motor driver, which drives the DC motor forward and in reverse. A separate PWM signal sets the servo angle, and the servo releases the mousetrap launcher.

Power

An AA battery pack runs the motor through the L298N, so motor current stays off the Arduino and does not pull its voltage down. The Arduino's regulated 5 V supplies the servo and the logic.

Reliability

Wiring was secured so it would not shake loose while driving. A loose-wire issue found during practice was fixed before the final runs.

Design decisions

Chassis

A decision matrix compared stability, weight, performance and build difficulty. A single-motor curved frame with a dual axle won on balance and smooth motion.

Launcher

A mousetrap gave consistent triggering and strong output. A servo was added so the launch fires from code instead of by hand.

Shell

Recycled cardboard, rope-tied panels for wiring access, and rounded edges. The painted theme drew on customized street cars.

What I learned

Mass decides performance

The day before test day the chair barely moved. A full rebuild that cut weight and simplified the chassis made it faster and far more consistent.

Practice the exact run

Repeating the speed run until it was reliable paid off with full marks. The speed bump was the one part that behaved differently on the day, so we would test that obstacle earlier next time.

Simple beats clever

String-tied bumpers meant to ease access kept coming loose and touching wires and wheels. A single lift-off shell would have been cleaner and safer.

Arduino code

The two sketches below are the code from the project report. Test 1 checked the rolling chassis and Test 2 added the servo launcher. Both run on an Arduino UNO driving an L298N motor driver.

Test #1 · Rolling chassis

Runs one timed drive cycle when the rocker switch is turned on: 3.65 s forward, a 0.25 s push, then a 6.5 s reverse pulse to stop.

// Test #1 - Rolling chassis
// Eco-Accessible Wheelchair (ENGG*1100, Team 8) - Arduino UNO + L298N motor driver
// Rocker switch ON (reads LOW) runs one drive cycle, then waits for the switch to be turned OFF.

int motor1pin1 = 2;
int motor1pin2 = 3;
int enablePin = 9;   // ENA pin
int switchPin = 7;   // TODO: this declaration is not shown in the report - set it to the pin your switch uses

void setup() {
  pinMode(motor1pin1, OUTPUT);
  pinMode(motor1pin2, OUTPUT);
  pinMode(enablePin, OUTPUT);
  pinMode(switchPin, INPUT);   // switch gives HIGH/LOW directly

  analogWrite(enablePin, 255); // full speed
}

void loop() {
  int switchState = digitalRead(switchPin);

  // Switch ON = LOW (if wired to GND)
  if (switchState == LOW) {

    // -------- RUN MOTOR FORWARD --------
    digitalWrite(motor1pin1, HIGH);
    digitalWrite(motor1pin2, LOW);
    delay(3650);

    digitalWrite(motor1pin1, HIGH);
    digitalWrite(motor1pin2, LOW);
    delay(250);

    // -------- REVERSE BRIEFLY TO SLOW / STOP --------
    digitalWrite(motor1pin1, LOW);
    digitalWrite(motor1pin2, HIGH);
    delay(6500);

    digitalWrite(motor1pin1, LOW);
    digitalWrite(motor1pin2, LOW);

    // -------- WAIT UNTIL SWITCH IS TURNED OFF --------
    while (digitalRead(switchPin) == LOW) {
      // do nothing, motor stays off
    }
  }
  else {
    // Switch OFF -> motor stays off
    digitalWrite(motor1pin1, LOW);
    digitalWrite(motor1pin2, LOW);
  }
}

// Test #2 - Launcher
// Eco-Accessible Wheelchair (ENGG*1100, Team 8) - Arduino UNO + L298N motor driver + servo
// Rocker switch ON (reads LOW): drive 2.8 s, pause 3 s to settle, then the servo turns to 30 degrees
// and releases the mousetrap launcher. Waits for the switch to be turned OFF before resetting.

#include <Servo.h>

int motor1pin1 = 2;
int motor1pin2 = 3;
int enablePin = 9;   // ENA pin
int switchPin = 7;   // TODO: this declaration is not shown in the report - set it to the pin your switch uses

Servo myServo;
int servoPin = 6;

void setup() {
  pinMode(motor1pin1, OUTPUT);
  pinMode(motor1pin2, OUTPUT);
  pinMode(enablePin, OUTPUT);
  pinMode(switchPin, INPUT);   // switch gives HIGH/LOW directly

  myServo.attach(servoPin);

  analogWrite(enablePin, 255); // full speed
}

void loop() {
  int switchState = digitalRead(switchPin);

  // Switch ON = LOW (if wired to GND)
  if (switchState == LOW) {

    // -------- DRIVE INTO POSITION --------
    digitalWrite(motor1pin1, HIGH);
    digitalWrite(motor1pin2, LOW);
    delay(2800);

    // -------- STOP AND LET THE CHAIR SETTLE --------
    digitalWrite(motor1pin1, LOW);
    digitalWrite(motor1pin2, LOW);
    delay(3000);

    // -------- FIRE THE LAUNCHER --------
    myServo.write(30);
    delay(500);

    // -------- WAIT UNTIL SWITCH IS TURNED OFF --------
    while (digitalRead(switchPin) == LOW) {
      // do nothing, motor stays off
    }
  }
  else {
    // Switch OFF -> motor stays off
    digitalWrite(motor1pin1, LOW);
    digitalWrite(motor1pin2, LOW);
  }
}

The report does not show the line that sets the switch pin, so the sketches use pin 7 as a placeholder. Change switchPin to the pin your switch is wired to. The report's rolling-chassis code also wrote the 0.25 s delay as 0250, which Arduino reads as octal, so it is written as 250 here to match the 0.25 s the report describes.
